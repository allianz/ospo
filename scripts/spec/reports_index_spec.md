# Spec: reports_index implementation

## Motivation

The HTML reports in `reports/<YYYY-MM>/` are self-contained, but GitHub shows `.html` files as source code. `reports/README.md`, which GitHub shows when the folder is opened, links every report through [htmlpreview.github.io](https://htmlpreview.github.io/), which renders a file of a public repository in the browser. The latest month comes first. The index is regenerated by `make create_reports`, so the report pull request always contains an index that matches its reports.

## Scope

The script:

- reads the month folders of the reports directory and the `<title>` of each `*-report.html`;
- writes `<reports>/README.md`: the reports of the latest month, and one line per earlier month.

Out of scope:

- Any call to GitHub or git. The script reads local files only.
- The content of the reports. The `data.json` files are not linked.

---

## CLI Interface

```
node scripts/reports_index.js --org <org> [--reports <dir>] [--debug]
```

| Flag | Default | Description |
|---|---|---|
| `--org` | required | Organisation of the reports, named in the introduction |
| `--reports` | `reports/` of the repo | Reports directory. Created when missing |
| `--config` | none | Accepted like in every script. Not used: the script has no configuration |
| `--dry-run` | false | Accepted like in every script. Has no effect: the script makes no changes on GitHub |
| `--debug` | false | Also print every month with the keys of its reports |

Exit codes: `0` on success, also without reports. `1` on a missing flag or a fatal error (for example an unreadable folder).

---

## Scan

- A month folder is a directory of the reports directory named `YYYY-MM`. Other files and folders are ignored.
- A report is a file `<key>-report.html` in a month folder. Its name is the HTML `<title>` up to the first ` · ` (without organisation and month), HTML entities unescaped; without a title, the key.
- Months are sorted latest first, reports by file name. A month folder without a report is left out.

---

## Output

`<reports>/README.md` is overwritten on every run. It contains:

1. An introduction naming the organisation, and a comment that the file is generated.
2. Without reports: "No reports yet."
3. `## Latest: <YYYY-MM>`: a list with one entry per report, the name linked to its htmlpreview URL.
4. `## Earlier months` (only when there are any): one line per month, the month linked to its folder, then the reports' names linked to their htmlpreview URLs.

The htmlpreview URL is `https://htmlpreview.github.io/?` followed by the blob URL of the file on `main` (`<GITHUB_SERVER_URL>/<GITHUB_REPOSITORY>/blob/main/reports/<YYYY-MM>/<key>-report.html`, default `https://github.com/allianz/ospo`). The README is published by merging the report pull request, so it links `main`. The links of a new month therefore only open after the merge; for the review, the pull request body of the [compliance report workflow](../../.github/workflows/compliance_report.yaml) links the reports on the branch `compliance-report`. htmlpreview can only load files of public repositories.

Console output:

```
Reports index: 2 months, latest 2026-11
Index written to reports/README.md
```

---

## Make target

`make create_reports` runs this script last, after all reports of the run, with `--org $(ORG) --reports $(REPORTS_DIR)`. The workflow commits `reports/`, so the index is part of the report pull request.
