Requirement status

Key messages

  • Baseline controls are fully in place. Access control, branch protection, public source, defect reporting and security contacts (GV.02, QA.02, QA.03, VM.01) are met for all 138 repositories. No configuration drift was found.
  • Release integrity is the main gap. 36 of 92 projects that publish releases provide no checksums, signatures or provenance (BR.03, MUST).
  • Peer review is at 84% (QA.06, SHOULD). 17 of the 22 affected repositories have only one maintainer.
  • Vulnerability handling worked as intended. 3 vulnerabilities were reported privately and published as advisories, after a median of 18 days.

Decisions requested

  1. Make artifact attestations mandatory for all releasing projects (BR.03). Proposal: OSPO provides a release workflow template; projects adopt it by 31 Mar 2027. Effort per project ≈ 0.5 day.
  2. Set a policy for single-maintainer projects (QA.06). Option A: require a second maintainer by 30 Jun 2027. Option B: accept a per-project deviation with post-merge review.

Status definitions

How the assessment works

  • Automated and repeatable. All automated checks run every week in one workflow, against every in-scope repository. Nothing is sampled.
  • Preventive and detective controls. Settings are enforced when a repository is provisioned (preventive). Weekly checks confirm they are still in effect (detective). Settings that cannot be read through an API are attested by hand every quarter.
  • Independent data source. OpenSSF Scorecard results are produced in each repository and published by OpenSSF. Anyone can verify them at scorecard.dev.
  • Traceable. Every figure in this report comes from the raw data files listed in Appendix C. The files are identified by SHA-256 hash and archived with this report.
